*Speed. A concrete, sound slice of ilyasergey/vermilion#6 (proof caching) that needs no
verdict reuse.*

`vrml_ladder` tries up to 13 rungs in a fixed order, each under its own
heartbeat budget (default `rungBudget` 50 000 units; `saturateBudget`
1 000 000; `smt` uncapped and without a timeout by default). An obligation
closed by a late rung (`nlinarith`, `scalar_saturate`, `smt`) pays for
every earlier rung's *failure* on every re-check: in the editor loop, in
`vrml_check`, and again in the twin check. The ladder already reports the
winner via `trace.vrml.ladder` ("discharged by {name}"), but nothing
consumes it.

### Proposal: a sidecar, with no change to the Lean text

The generated block bodies must stay byte-stable:

- `vrml_sync` copies them into twins;
- `twin_covers` treats `twin_body != generated_body` as a hand-written
  proof;
- `--skip-identical` relies on byte equality;
- the plan requires generated bytes to be deterministic, not dependent on
  run history.

So the hint must **not** be rendered into the tactic call. Instead:

- `vrml_check` collects the `discharged by` trace per obligation and writes
  `{statement_hash → rung}` to a sidecar, for example
  `.vermilion/rung-hints.json` (gitignored, like the other run state).
- The ladder reads the sidecar at elaboration time, either through an
  option passed with `-D` (as `vrml_check` already does for the budgets)
  or through an environment extension loaded once per process. It looks
  up the current goal's statement hash (`ObligationMeta.statementHash` of
  the enclosing declaration), tries that rung first, and falls back to the
  full order on failure.
- This is not a verdict cache. Every proof is still produced and
  kernel-checked on every run, so no stale verdict can be replayed: the
  concern `plans/execution-plan.md` raises about the removed cache does not
  apply. A wrong or stale hint only costs one failed rung.

### Measure

On the differential corpus and the dalek-lite Layer A units, record cold
versus warm-hint `vrml_check` wall time and the per-rung histogram. Add both
to `docs/reports/performance-ledger.md`.

Related: ilyasergey/vermilion#6 proof caching; `plans/incremental-computation.md` (item 3,
persistent workers, is complementary: it removes the import cost, while
this removes repeated rung failures).
